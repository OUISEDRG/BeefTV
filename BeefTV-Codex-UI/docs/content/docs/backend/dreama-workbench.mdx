---
title: 剧梦专用工作台
description: 本地画布的剧梦项目绑定、能力参数、任务执行和定制版本维护。
---

工作台保留 BeefTV 的画布、素材、时间线和助手。一张画布绑定一个剧梦项目，默认剧集用于未分组生成节点；剧集分组通过实际父子成员关系指定目标剧集。共享素材的连线不会改变目标生成节点的剧集。绑定采用 `integrations.dreama` v1，并通过画布正式文档提交和 revision 冲突检查保存；更换项目需要复制画布重新绑定。

## 参数与引用

目录只发布平台已验证、桥接已实现的能力。图片分辨率保留平台原始档位；音频按显式能力声明显示音色、格式和速度；增强无需占位提示词，延长时长是新增片段时长。模型变体保留各自限制，不能因刷新目录而改写已有任务。

引用沿用画布稳定 token 编译。最终图片数组、人物音色索引和生成快照使用同一次编译结果。纯文本正文不自动润色或补段落，旧编号缺少唯一关联时在提交前报错。预览选中节点不会创建远端分镜或收费任务。

## 工具可用范围

工具栏按当前渠道的实际执行能力显示。剧梦图片的视角转换、重打光和人物质感使用参考图生成：创建独立节点、继承原图所在分组，将原图引用和调整要求写入可见提示词，再进入普通画布生成入口。重打光和人物质感先创建可编辑草稿；视角转换在提交前展示调整要求。人物质感滑块只更新明确标记的工具提示段落，保留用户补充正文。图片上的原有音色绑定继续保留，不作为图片生成的声音参数发送。

原图、剧集绑定或已保存参数需要修正时，工具提前禁用并说明原因。删除渠道不会自动改用其他渠道。工具生成的已完成图片可以继续作为新的原图；现有草稿再生成时仍验证自己的原图、连线和可见引用。旧版隐藏人物质感配置不会自动改写正文，需要从原图重新建立工具节点。

尚未接入的蒙版局部重绘、精确表情编辑、视频局部编辑和草稿转成片从剧梦工具栏隐藏，执行函数也拒绝旧入口调用。视频延长选择已配置的剧梦延长协议，保留原视频及剧集分组。AI 超分依赖独立 BeefAPI 能力，未配置该能力时不显示；本地图片缩放、裁剪、标注、分割及视频提帧、裁剪、剪辑、提取音频等仍按各自依赖状态工作。

本机 Codex 文本桥接支持文本和图片，当前不接受视频附件，因此其视频反推入口隐藏，图片反推保留。剧梦生成不提供隐式追加摄影、运镜或技能正文的控件；旧节点需要显式关闭旧摄影设置，并把技能需求写成可见正文后移除技能引用。正文不会在迁移时自动改变。

独立 AI 全景、可复用工作流中的剧梦生成和助手的整片后台自动制作尚未传递画布绑定与最终引用快照，因此相关生成入口关闭。工作流中的本地媒体处理与可用的文本能力保留；普通助手生成提议、批量表格和现有分镜节点继续经过画布生成入口。已经接受的任务继续按原任务身份恢复，禁止以旧工作流配方绕过绑定发起新任务。

## 本机 API

`/api/integrations/dreama/v1` 使用工作区权限和标准 `{code,data,msg,reason}` 信封。GET 的 `channelId` 在查询参数中，POST 在 JSON 正文中；浏览器不提供 URL、密钥或可执行路径。

| 方法与路径 | 行为 |
| --- | --- |
| GET status | 桥接与账本能力状态 |
| GET projects | 项目列表和模式 |
| GET series?projectId=… | 指定项目的剧集 |
| POST series | 按明确项目与名称新建剧集 |
| GET catalog | 版本化模型能力目录 |
| POST catalog/refresh | 携带 expectedRevision，更新同一连接的已保存剧梦渠道 |
| GET tasks?canvasId=… | 当前画布的脱敏任务状态 |
| POST tasks/:id/cancel | 取消仍可取消的本地阶段；不伪装远端取消 |
| POST ensure | 复用服务，或使用安装器保存的运行配置隐藏启动 |

生成仍进入原来的 BeefTV 任务与插件协议。`providerOptions.dreama` 保存 v1 绑定快照；Python 账本唯一负责收费提交、倒计时和远端对账。未知回执不重新提交，产物下载失败不重新生成。模型目录刷新只更新模型及 profile，不替换密钥、其他渠道或默认模型。

## 运行与版本维护

安装器在数据目录保存 `dreama-integration.json`，包含本机 Python、桥接目录和固定回环来源，不包含剧梦密钥。设置凭据继续来自已保存渠道。Python 桥接是独立进程，关闭画布面板不停止任务。

维护工具 `scripts/dreama_release.py` 支持：

- `check-upstream --repository <源码>`：读取官方稳定 tag，不修改运行版本。
- `prepare-upgrade --repository <源码> --tag <稳定版本> --directory <新目录>`：补齐 Git 历史，在隔离分支合并；有冲突时保留现场，不安装。
- `package` / `verify`：记录并校验程序、Agent、CLI、插件、桥接及 Codex 代码的哈希和源版本。
- `install`：要求程序与桥接已停止且没有活动任务，备份后安装完整包，保留数据库、配置及原账本。
- `activate --app <安装目录> --backup <本次备份> --channel-id <启用的剧梦渠道>`：打开新程序后，使用已有 CLI 客户端授权，通过正式插件 API 安装包内剧梦协议插件，核对版本和哈希，启动桥接，再以当前 revision 刷新目录。此步骤完成才算安装验收；失败可用同一命令重试，不会提交生成。
- `rollback`：先检查旧程序能否读取现有账本和画布绑定，再恢复程序文件；不覆盖安装后新增的任务或数据。

发布清单的 `desktopSchemaVersion` 从本次桌面源码读取。安装与回退在替换文件前，只读核对 `local_schema_migrations` 中的当前版本；目标程序支持的版本较低，或旧清单未声明读取能力时，不会替换已经升级数据库的程序，需使用兼容恢复包。回退不删除迁移记录，也不覆盖安装后新增的审计或任务数据。

`scripts/build-dreama-workbench.ps1` 先用实际 Go 协议编译器验证独立桥接 manifest 的五种媒体请求，再调用完整的 Windows 官方构建链，并关闭官方自动覆盖更新。构建需要既有 Go、Bun、CGO、Node 和 Wails 工具链；更新包必须在回归通过后安装。新协议账本不能交给不认识它的旧桥接，必要时使用兼容的新恢复版本，而不是删除账本降级。动态目录缓存在桥接的 `state/capability-cache-v1.json`，与账本一样保留，不用旧版本静态目录覆盖。

旧的暂停预检和回执不明任务保留原绑定，不随新默认项目迁移。升级前的只读账本检查区分活动任务和待核验历史记录；待核验记录可以随兼容升级保留，不能被当成新请求重放。

剧梦协议包单独位于 `dreama-integration/dreama-modalities.beeftv-plugin`，其版本和哈希写入发布清单。若新旧协议注册不同，回退工具拒绝恢复旧插件数据库，要求使用兼容恢复包；它不会用旧备份覆盖新任务或插件权限记录。恢复画布历史只恢复可编辑内容，当前剧梦项目绑定与绑定版本保持有效。

离线测试、真实只读核验、实际生成效果分别验收。维护和开发测试不发起收费试生成。

## 本地发布产物保留

`scripts/dreama_retention.py` 管理专用工具目录 `BeefTV-Codex-UI-tools` 下的 `releases`、`backups` 和 `go-cache`。默认只输出预览；加 `--apply` 才执行删除。目录中必须已有本机策略 `dreama-retention.json`，策略及真实路径不提交 Git：

```json
{
  "schemaVersion": 1,
  "toolsRoot": "<专用工具目录绝对路径>",
  "app": "<正式应用绝对路径>",
  "protectedPaths": ["<数据目录绝对路径>", "<源码及其他工作树绝对路径>"],
  "cacheMaxAgeHours": 24
}
```

```powershell
python scripts/dreama_retention.py --tools-root <专用工具目录>
python scripts/dreama_retention.py --tools-root <专用工具目录> --apply
```

完整发布包按清单 `createdAt` 排序，同一时刻优先 `-final`；保留最新一份，并保留与正式应用 `dreama-release.json` 完全匹配的包。因此打包成功、尚未安装时可能暂存两份。正式应用清单缺失或格式无法识别时保留所有发布包。备份分别保留最新一份完整的 `dreama-时间戳` 部署备份和 `current-workspace-时间戳` 工作区备份。文件哈希、清单、工作区数据库或完整性校验失败的目录保留并报告，不能让不完整新备份淘汰已有有效备份。

发布包与备份的文件清单必须覆盖各自程序、桥接、Codex 或数据子目录中的全部文件。未知顶层目录、未列入清单的文件、Git 标记、符号链接或 Windows 重解析点都阻止该目录被删除。策略中的 `protectedPaths` 应包含实际数据、源码、桥接、全部工作树及需要长期保留的演练目录；删除目标与这些路径重叠时拒绝处理。程序在删除前再次核对完整清单及哈希，预览不会生成锁文件。

旧包如包含额外交付证据，需经过人工核对后，在本机策略的 `releaseExtraFiles` 中按发布目录名记录每个 `evidence/相对文件` 和 `更新交付记录.md` 的 SHA256。旧部署备份的根目录附件同理记入 `backupExtraFiles`：按备份目录名列出除 `record.json`、`rollback.json` 外每个直属文件的 SHA256。工作区备份只允许额外登记已在 `record.databases` 中声明的数据库对应的 `-wal`、`-shm` 文件及哈希。两个字段都使用 `{ "目录名": { "相对文件": "SHA256" } }` 结构；缺少、增加或修改附件都会保留该目录。新安装自动将这些附件哈希写入备份记录的 `supplementalHashes`，无需人工登记。此登记不修改历史备份内容。

配置策略后，`dreama_release.py` 在发布包验证通过、或安装完成并保存成功记录后自动应用此策略。打包、安装、回退和激活共用排他锁；`build-dreama-workbench.ps1` 的完整构建阶段也持有同一个锁。安装或打包失败不会触发清理，清理失败也不会把已完成安装报告成安装失败。独立维护命令遇到锁冲突会退出并报告，下一次运行可重试。

Go 缓存只清理标准十六进制分桶中超过 `cacheMaxAgeHours` 的标准哈希缓存文件。检测到 Go、Bun、Wails 或相关编译器进程，或者无法确认进程状态时，应用清理会跳过；运行中的应用、数据库、上传素材、插件运行数据及其他工具目录不在清理范围。可以由 Windows 任务计划程序每天调用带 `--apply` 的命令，使用当前用户身份并禁止同一任务并发；无需重新复制工具或源码。其他自定义构建入口也应遵守同一排他锁，避免在独立维护运行期间启动编译。

安全回归使用临时目录，可运行 `python -B scripts/test_dreama_retention.py` 和 `python -B scripts/test_dreama_release.py`；这些测试不读取或修改实际安装数据。
